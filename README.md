# 📖 دليل حمص الشامل (Homs Directory)

تطبيق ويب متكامل (Full-Stack Web Application) تم تصميمه وتطويره ليكون الدليل الرقمي الأول لمدينة حمص. يهدف المشروع إلى تسهيل وصول المستخدمين إلى الخدمات، المهن، والمحلات التجارية في المدينة من خلال واجهة مستخدم تفاعلية، سريعة، وسهلة الاستخدام، مع لوحة تحكم متكاملة لإدارة البيانات.

![Homs Directory Preview](https://via.placeholder.com/800x400?text=Homs+Directory+Preview)

## ✨ الميزات الأساسية (Key Features)

* **بحث وفلترة متقدمة:** بحث فوري (Real-time) بالاسم، وتصفية النتائج حسب "الفئة" و "المنطقة".
* **لوحة تحكم آمنة (Admin Dashboard):** نظام مصادقة يعتمد على (Token-based Authentication) لحماية مسارات التعديل والحذف.
* **إدارة البيانات (CRUD Operations):** إمكانية إضافة، تعديل، وحذف العملاء والخدمات من واجهة المستخدم مباشرة.
* **تصدير واستيراد البيانات (Excel Integration):** التعامل مع البيانات الضخمة عبر رفع ملفات `.xlsx` لتحديث الدليل، وتصدير البيانات الحالية بنقرة واحدة باستخدام مكتبة `SheetJS`.
* **تطبيق ويب تقدمي (PWA):** إمكانية تثبيت الموقع كتطبيق على الهواتف الذكية (Installable App) لتجربة استخدام تشبه التطبيقات الأصلية.
* **تكامل سلس للتواصل:** أزرار ديناميكية للاتصال المباشر أو تحويل المستخدم إلى محادثة "واتساب" عبر روابط مخصصة (`wa.me`).

## 🛠️ التقنيات المستخدمة (Tech Stack)

### واجهة المستخدم (Front-End)
* **React.js:** لبناء واجهات تفاعلية تعتمد على المكونات (Components).
* **Tailwind CSS:** لتصميم متجاوب (Responsive) وحديث يدعم الأجهزة المحمولة.
* **Lucide React:** لمكتبة الأيقونات.
* **XLSX (SheetJS):** لمعالجة وقراءة ملفات الإكسل برمجياً.

### الخادم (Back-End)
* **Node.js & Express.js:** لبناء خادم API سريع للتعامل مع الطلبات.
* **CORS & JSON Parsing:** لمعالجة الطلبات القادمة من الواجهة الأمامية بأمان.

### قاعدة البيانات (Database)
* **PostgreSQL:** قاعدة بيانات علائقية قوية (مستضافة سحابياً عبر Neon.tech).

### الاستضافة (Hosting)
* **Netlify:** لاستضافة الواجهة الأمامية (Frontend) مع دعم الـ CI/CD.
* **Render:** لاستضافة الخادم (Backend).

## 🗄️ بنية قاعدة البيانات (Database Schema)

يعتمد النظام على جدول `listings` المصمم لتخزين بيانات العملاء بكفاءة:

| الحقل (Column) | النوع (Type) | الوصف (Description) |
| :--- | :--- | :--- |
| `id` | `SERIAL PRIMARY KEY` | المعرف الفريد لكل خدمة/عميل. |
| `full_name` | `VARCHAR(150)` | الاسم الكامل أو اسم المحل التجاري. |
| `category` | `VARCHAR(100)` | التصنيف (مثال: طب، محاماة، صيانة...). |
| `region` | `VARCHAR(100)` | المنطقة الجغرافية داخل المدينة. |
| `detailed_address` | `TEXT` | العنوان التفصيلي بدقة. |
| `phone_number` | `VARCHAR(20)` | رقم الهاتف للتواصل. |
| `map_url` | `TEXT` | رابط موقع العميل على خرائط جوجل. |
| `created_at` | `TIMESTAMP` | تاريخ ووقت إضافة السجل تلقائياً. |

## 🧠 التحديات والحلول (Challenges & Solutions)

خلال فترة تطوير هذا المشروع، واجهت عدة تحديات برمجية وهندسية قمت بحلها بفعالية:

1. **إدارة اتصال قاعدة البيانات في بيئات مقيدة (ECONNRESET):**
   * **التحدي:** قيام مزودات خدمة الإنترنت (ISPs) بحظر الاتصالات الصادرة إلى خوادم قواعد البيانات السحابية أثناء التطوير المحلي، مما أدى إلى خطأ `ECONNRESET`.
   * **الحل:** تم هيكلة الخادم ليعمل بكفاءة عبر الاستضافة السحابية (Render) التي تتصل بقاعدة بيانات (Neon PostgreSQL) في نفس النطاق الجغرافي السحابي، مما لغى مشكلة الحظر المحلي ووفر اتصالاً مستقراً وآمناً بأجزاء من الثانية.

2. **أمان مسارات الحذف الشامل (Route Security & Data Integrity):**
   * **التحدي:** الحاجة إلى ميزة "مسح كل البيانات" لتحديث الدليل، مع ضمان عدم تنفيذها بالخطأ أو من قبل أشخاص غير مصرح لهم.
   * **الحل:** تم حماية نقطة النهاية (Endpoint) `/api/listings/all` بنظام مصادقة (Token)، وتم ترتيبها برمجياً فوق مسارات الحذف الفردي لمنع تضارب الـ Routing في `Express`. في الواجهة الأمامية، تمت إضافة طبقة حماية مزدوجة (Double-Confirmation Prompts) لضمان تأكيد المدير قبل مسح قاعدة البيانات.

3. **معالجة البيانات غير المهيكلة (Sanitizing Excel Uploads):**
   * **التحدي:** عند استيراد البيانات عبر ملفات Excel، قد تحتوي الحقول على مسافات زائدة أو قيم مفقودة تؤدي إلى انهيار قاعدة البيانات.
   * **الحل:** بناء دالة وسيطة في واجهة المستخدم تقوم بتنظيف أسماء الأعمدة (Trimming)، واستبدال الحقول المفقودة بقيم افتراضية (Fallback Values) قبل إرسال الـ Payload إلى الخادم، مع تصفية الصفوف الفارغة برمجياً `filter(item => item.full_name !== "")`.
